# 基金组合实验室产品设计

日期：2026-06-04
状态：待用户审阅

## 1. 产品定位

基金组合实验室是一个本地自用的多资产基金组合研究工具。

第一版聚焦进取型配置：

```text
权益 / QDII：75%
债券基金：15%
黄金基金：10%
```

它不是基金销售、投顾或交易系统。它不提供买卖建议，不自动下单，不做公开基金推荐，也不为其他用户提供个性化投资建议。

第一版要回答的核心研究问题是：

```text
在 75% 高风险基金仓位的基础上，
加入 15% 债券和 10% 黄金，
历史上是否能有效降低回撤，并且不过度牺牲长期收益？
```

## 2. 第一版目标

第一版要支持一条完整的个人研究闭环：

```text
维护个人基金池
-> 获取或导入历史净值
-> 给基金打资产桶标签
-> 创建组合实验
-> 按再平衡规则跑回测
-> 和基准组合做对比
-> 生成 Markdown 风格研究报告
```

核心目标：

- 维护一个个人精选基金池，而不是抓取全市场基金。
- 支持单基金画像，用于理解基金的收益、波动和回撤特征。
- 基于历史净值回测自定义基金组合。
- 对比默认 75/15/10 组合、纯权益/QDII 组合、无黄金组合。
- 评估债券和黄金在历史压力阶段是否真正起到防守作用。
- 为每次组合实验生成一份简洁的个人研究备忘录。

非目标：

- 不做自动交易。
- 不做公开基金推荐流。
- 不做账号体系、多租户、支付或公开 SaaS 流程。
- 第一版不做全市场主动基金排名。
- 第一版不做基金经理画像系统。
- 第一版不做深度持仓穿透。
- 第一版不做实时盘中净值估算。

## 3. 默认研究框架

默认基准配置为：

```text
A 股权益基金：45%
海外 / QDII 权益基金：30%
债券基金：15%
黄金基金：10%
```

高层仍然按 75/15/10 组合理解：

```text
权益 / QDII：75%
债券：15%
黄金：10%
```

A 股权益和海外 QDII 的比例应允许在每次实验中调整，因为二者的风险来源不同：

- A 股权益：国内权益周期、政策敏感度、行业暴露。
- 海外 / QDII 权益：海外权益周期、汇率影响、净值滞后、QDII 额度和假期差异。
- 债券基金：利率风险、信用风险、防守资产角色。
- 黄金基金：商品属性、货币属性、避险或分散化特征。

## 4. 核心用户流程

### 4.1 基金池管理

用户维护自己的个人基金池。

每只基金需要包含：

- 基金代码。
- 基金名称。
- 资产桶。
- 可选自定义标签。
- 可选备注。
- 是否启用。

第一版支持的资产桶：

- A 股宽基权益。
- A 股行业 / 主题权益。
- 主动权益。
- 海外 / QDII 权益。
- 债券。
- 黄金 / 商品。
- 货币 / 现金替代。

第一版允许手动打标签。对于自用研究工具，手动维护标签通常比依赖公开数据自动推断更可靠。

### 4.2 单基金画像

基金池中的任意基金都可以查看单基金画像。

展示内容：

- 净值曲线。
- 累计收益。
- 年化收益。
- 年化波动率。
- 最大回撤。
- 夏普比率。
- 卡玛比率。
- 近 1 个月、3 个月、6 个月、12 个月收益。
- 数据足够时展示最长回撤修复天数。

这个页面不是第一版的主界面。它主要用于在组合实验前检查单只基金的历史特征。

### 4.3 组合实验

用户通过选择基金和设置目标权重来创建组合实验。实验不应孤立存在，而应归属于一个实验组。

实验组用于表达同一研究问题下的一组主实验、基准实验和变体实验。例如：

```text
实验组：进取型 75/15/10 防守资产测试

主实验：
75/15/10 月度再平衡

基准实验：
100% 权益/QDII
75/25/0 无黄金
75/15/10 不再平衡
75/15/10 季度再平衡
```

每个实验需要有角色：

- main：主实验。
- benchmark：基准实验。
- variant：变体实验。

系统需要校验：

- 目标权重合计为 100%。
- 每只基金都有足够的重叠历史净值。
- 每只基金都已经设置资产桶。
- 再平衡规则合法。
- 同一实验组中的实验具有可比较的回测区间和净值口径。

第一版支持的再平衡规则：

- 不再平衡。
- 月度再平衡。
- 季度再平衡。
- 权重绝对偏离 5% 时再平衡。
- 权重绝对偏离 10% 时再平衡。

第一版的交易成本模型保持简单：

- 默认成本为 0。
- 可选配置单只基金的单边成本。
- A/C 类份额成本比较暂不纳入第一版。

### 4.4 回测看板

回测结果需要展示：

- 组合净值曲线。
- 回撤曲线。
- 年化收益。
- 年化波动率。
- 最大回撤。
- 夏普比率。
- 卡玛比率。
- 年度收益。
- 月度收益热力图。
- 按资产桶拆分的收益贡献。
- 按基金拆分的收益贡献。
- 总调仓幅度。
- 单边换手率。
- 估算交易成本。
- 数据质量等级。

看板需要方便完成三组核心对比：

```text
75/15/10 vs 100% 权益/QDII
75/15/10 不再平衡 vs 月度再平衡 vs 季度再平衡
75/15/10 vs 75/25/0，用于隔离黄金的作用
```

### 4.5 防守资产诊断

这个视图专门回答债券和黄金是否有效。

系统需要识别组合回撤区间，并计算：

- 回撤区间内的组合收益。
- 回撤区间内债券资产桶的贡献。
- 回撤区间内黄金资产桶的贡献。
- 回撤区间内权益 / QDII 资产桶的贡献。
- 防守资产是否降低了组合回撤。
- 防守资产是否造成了明显长期收益拖累。

第一版还需要支持手动定义压力区间，例如：

- 2018 年 A 股熊市。
- 2020 年疫情冲击。
- 2021-2022 年港股 / 中概互联网回撤。
- 2022 年全球加息阶段。
- 2024 年 A 股和港股波动阶段。

压力区间应保存为可配置日期范围，不应硬编码在计算逻辑里。

### 4.6 研究报告

每次完成组合实验后，可以生成一份 Markdown 风格研究报告。

报告内容包括：

- 实验名称。
- 基金列表和目标权重。
- 再平衡规则。
- 回测日期范围。
- 核心收益和风险指标。
- 与基准组合的对比。
- 主要收益贡献来源。
- 主要回撤贡献来源。
- 防守资产诊断。
- 后续观察事项。

报告语言应保持研究口径：

- “观察”。
- “风险暴露”。
- “历史回撤”。
- “再平衡模拟”。
- “后续实验可继续观察”。

报告语言应避免：

- “买入”。
- “卖出”。
- “推荐基金”。
- “保证收益”。
- “跟投组合”。

## 5. 数据模型

第一版只需要较小的数据模型。

### 5.1 fund_basic

存储基金身份信息和用户维护的元数据。

字段：

- fund_code：基金代码。
- fund_name：基金名称。
- fund_type：基金类型。
- asset_bucket：资产桶。
- inception_date：成立日期。
- fund_company：基金公司。
- is_active：是否启用。
- note：备注。
- created_at：创建时间。
- updated_at：更新时间。

### 5.2 fund_nav_daily

存储基金每日净值数据。

字段：

- fund_code：基金代码。
- nav_date：净值日期。
- unit_nav：单位净值。
- accumulated_nav：累计净值。
- adjusted_nav：复权净值。
- source：数据来源。
- created_at：创建时间。
- updated_at：更新时间。

回测引擎应优先使用复权净值，但同一个实验中不应默认混用不同净值口径。

净值口径规则：

- 优先尝试所有基金统一使用复权净值。
- 如果部分基金缺少复权净值，提示用户改用累计净值统一回测，或剔除缺少复权净值的基金。
- 如果累计净值也无法统一，再提示用户是否使用单位净值。
- 如果用户明确允许混用净值口径，结果必须标记为低置信度，并在报告中展示每只基金实际使用的净值口径。

回测结果需要保存本次实际使用的净值口径，例如：

```json
{
  "preferred": "adjusted_nav",
  "actual_used": {
    "000001": "adjusted_nav",
    "000002": "accumulated_nav",
    "000003": "unit_nav"
  },
  "mixed_policy": true
}
```

### 5.3 experiment_group

存储同一研究问题下的一组实验。

字段：

- experiment_group_id：实验组 ID。
- group_name：实验组名称。
- research_question：研究问题。
- note：备注。
- created_at：创建时间。
- updated_at：更新时间。

### 5.4 portfolio_experiment

存储一次研究实验。

字段：

- experiment_id：实验 ID。
- experiment_name：实验名称。
- experiment_group_id：所属实验组 ID。
- role：实验角色，可选 main、benchmark、variant。
- start_date：开始日期。
- end_date：结束日期。
- rebalance_rule：再平衡规则。
- cost_model：成本模型。
- note：备注。
- created_at：创建时间。
- updated_at：更新时间。

### 5.5 portfolio_position

存储每个实验的目标权重。

字段：

- experiment_id：实验 ID。
- fund_code：基金代码。
- target_weight：目标权重。
- asset_bucket_snapshot：实验创建时的资产桶快照。

### 5.6 stress_period

存储可配置的压力区间。

字段：

- period_id：压力区间 ID。
- period_name：压力区间名称。
- start_date：开始日期。
- end_date：结束日期。
- description：区间说明。
- is_active：是否启用。
- created_at：创建时间。
- updated_at：更新时间。

示例：

- 2018 年 A 股熊市。
- 2020 年疫情冲击。
- 2021-2022 年港股 / 中概互联网回撤。
- 2022 年全球加息阶段。
- 2024 年 A 股和港股波动阶段。

### 5.7 backtest_result

存储回测指标和输出结果。

字段：

- result_id：结果 ID。
- experiment_id：实验 ID。
- run_time：运行时间。
- metrics_json：指标结果。
- contribution_json：贡献拆解结果。
- rebalance_records_json：再平衡记录。
- nav_policy_json：净值口径结果。
- missing_data_json：缺失数据诊断。
- data_quality_level：数据质量等级。
- data_quality_json：数据质量说明。
- report_markdown：研究报告内容。

第一版可以使用 JSON 字段保存贡献、调仓记录和诊断说明。这样在研究模型还会变化时，数据库结构更灵活。

### 5.8 backtest_nav_daily

存储回测日度净值和回撤结果。

字段：

- result_id：结果 ID。
- nav_date：日期。
- portfolio_nav：组合净值。
- portfolio_return：组合日收益率。
- drawdown：当前回撤。

日度净值和回撤单独建表，方便多实验对比画图、查询压力区间表现，以及后续生成报告。

## 6. 计算规则

### 6.1 收益率序列

单基金日收益率按所选净值序列计算：

```text
daily_return[t] = nav[t] / nav[t-1] - 1
```

组合日收益率按实际权重计算。发生再平衡时，实际权重重置为目标权重。

### 6.2 重叠数据区间

默认使用所有选中基金共同拥有数据的日期区间。

如果某只基金成立较晚，系统不能在其成立前静默填充数据。有效回测区间必须在结果中明确展示。

### 6.3 缺失净值

缺失净值处理规则：

- 按交易日期对齐所有基金。
- 只允许在基金已经成立且后续仍有净值的情况下，对短缺口做前向填充。
- 不允许在基金成立前前向填充。
- 在结果元数据中记录缺失数据数量、前向填充次数和最长连续填充天数。

缺失数据诊断至少区分以下类型：

- fund_not_started：基金尚未成立。
- holiday_gap：假期或非交易日导致缺失。
- nav_delay：QDII 净值滞后。
- random_missing：异常缺失。
- long_gap：连续多日缺失。

第一版不要求完全自动准确分类，但报告中至少需要展示：

- 本次回测区间。
- 共同有效交易日数量。
- 前向填充次数。
- 最长连续填充天数。
- 涉及 QDII 基金数量。
- 异常缺失或长缺口基金列表。

QDII 基金可能存在净值滞后或假期不同步，所以缺失数据诊断必须在报告中可见。

### 6.4 指标

第一版指标：

- 累计收益。
- 年化收益。
- 年化波动率。
- 最大回撤。
- 夏普比率。
- 卡玛比率。
- 最佳月份。
- 最差月份。
- 正收益月份占比。
- 可计算时展示最长回撤修复天数。

无风险利率第一版默认设为 0，后续可以配置。

### 6.5 再平衡、换手率和成本

再平衡发生前，系统先根据各基金当日收益更新当前权重。若触发再平衡，则将当前权重重置为目标权重。

单只基金调仓幅度：

```text
rebalance_trade_weight_i = abs(target_weight_i - current_weight_i)
```

单次总调仓幅度：

```text
total_rebalance_trade_weight = sum(rebalance_trade_weight_i)
```

单边换手率：

```text
one_side_turnover = sum(abs(target_weight_i - current_weight_i)) / 2
```

估算交易成本：

```text
cost = sum(rebalance_trade_weight_i * single_side_cost_rate_i)
```

报告中应同时展示：

- 总调仓幅度。
- 单边换手率。
- 估算交易成本。

基金申购、赎回、销售服务费的真实规则更复杂。第一版只做可配置的简单单边成本，A/C 类份额成本比较后续再做。

### 6.6 收益贡献拆解

第一版采用简单、可解释的日度贡献口径。

单只基金日度贡献：

```text
daily_contribution_i = weight_i_before_return * daily_return_i
```

组合日收益：

```text
portfolio_return = sum(daily_contribution_i)
```

区间贡献可以先使用日度贡献的累计或复合近似。长期区间贡献会受到复利影响，不能视为严格归因。

报告中需要说明：

```text
收益贡献为基于日度持仓权重和日收益率的近似归因。
```

第一版不做 Brinson 归因、持仓穿透归因或复杂因子归因。

### 6.7 数据质量等级

每次回测都需要输出数据质量等级。

等级定义：

- A：数据完整，统一净值口径，缺失较少。
- B：存在少量前向填充或 QDII 日期错位，但不影响主要结论。
- C：净值口径混用，或缺失较多，结果仅供粗略观察。
- D：数据质量过低，拒绝生成正式回测报告。

报告需要展示数据质量等级和原因，例如：

```text
本次回测数据质量：B
原因：
- 2 只 QDII 基金存在净值滞后
- 共发生 18 次短缺口前向填充
- 所有基金统一使用累计净值
```

当数据质量为 D 时，系统可以保存诊断结果，但不生成正式研究报告。

## 7. 技术架构

因为这是本地自用研究工具，第一版架构应该优先保证迭代速度和计算正确性，而不是企业级结构。

推荐第一版结构：

```text
前端：
本地 Web UI，用于基金池、实验组、组合实验、回测看板和报告展示。

后端 / API：
FastAPI 本地服务，提供基金、实验组、实验、回测、压力区间和报告接口。

量化计算模块：
Python 计算模块，使用 pandas / numpy。

数据库：
PostgreSQL 作为正式本地运行数据库。
SQLite 可作为单元测试数据库。

数据导入：
先支持 CSV 手动导入，再支持 AKShare 脚本导入，Tushare 作为后续可选增强。
```

第一版可以从本地单体开始：

```text
本地 Web 应用 -> FastAPI -> 量化计算模块 -> PostgreSQL
```

如果项目后续变成更完整的平台，可以再引入 Spring Boot 作为主服务骨架。对于第一条研究闭环，Python-first 后端更快。

## 8. 错误处理

重要错误需要在界面和报告元数据中明确展示：

- 基金代码不存在。
- 净值数据不可用。
- 重叠历史区间不足。
- 组合权重合计不等于 100%。
- 再平衡规则无法应用。
- 缺失净值比例过高。
- 当前基金池无法构建所选基准组合。
- 实验组内实验无法对齐回测区间。
- 净值口径无法统一且用户未允许低置信度混用。
- 数据质量等级为 D。

当结果可能误导用户时，回测应明确失败。系统不应静默生成一条由无效数据拼出来的长周期回测。

## 9. 测试策略

第一版测试重点放在计算正确性。

必需测试：

- 日收益率计算。
- 最大回撤计算。
- 年化收益和年化波动率计算。
- 组合加权收益计算。
- 月度和季度再平衡行为。
- 阈值再平衡行为。
- 缺失净值对齐行为。
- 净值口径选择和混用拦截。
- 数据质量等级计算。
- 单边换手率和估算交易成本计算。
- 已知回撤区间内的贡献计算。

有用的测试样例：

- 两只基金组成、可以手工计算收益的组合。
- 含缺失日期的基金。
- 成立日期较晚的基金。
- 净值口径不完整的基金组合。
- 包含 QDII 净值滞后的基金组合。
- 一个不再平衡和月度再平衡结果应明显不同的组合。

人工校验：

- 跑一个已知组合，检查净值、回撤和贡献图是否符合预期。
- 至少把一组指标结果和独立电子表格计算结果做对照。

## 10. 第一里程碑范围

第一里程碑完成时，用户应能做到：

1. 添加一个小型个人基金池。
2. 导入或获取这些基金的历史净值。
3. 给每只基金设置资产桶。
4. 创建一个包含主实验、基准实验和变体实验的实验组。
5. 创建一个 75/15/10 主实验。
6. 自动或半自动创建 100% 权益/QDII、75/25/0、不同再平衡频率等基准实验。
7. 跑不再平衡、月度再平衡和季度再平衡回测。
8. 查看统一指标表、收益、回撤、贡献和防守资产诊断。
9. 查看每个实验的数据质量等级、净值口径和缺失数据诊断。
10. 生成一份 Markdown 研究报告。

这个里程碑不包含公开分享、账号系统、自动交易、基金推荐话术或全市场筛选。

工程化验收标准：

1. 至少支持 10 只基金的本地基金池。
2. 至少支持 3 个资产桶：权益/QDII、债券、黄金。
3. 可以完成一组 75/15/10 主实验。
4. 可以生成 100% 权益/QDII、75/25/0、不同再平衡频率基准实验。
5. 所有实验都输出统一指标表。
6. 任意实验都能导出 Markdown 报告。
7. 至少一组结果与 Excel 手工计算对照通过。
8. 缺失数据和净值口径必须在报告中可见。
9. 数据质量为 D 时拒绝生成正式报告。
10. 报告中不出现“买入”“卖出”“推荐”“保证收益”等表达。

## 11. 待实施前确认的问题

以下实施方向已经确认：

- 正式本地运行数据库使用 PostgreSQL。
- SQLite 可用于单元测试。
- 第一版采用 Python-first，使用 FastAPI + pandas/numpy。
- 数据导入顺序为 CSV 手动导入 -> AKShare 脚本导入 -> Tushare 可选增强。
- 第一批基金池控制在 12 到 20 只以内。

进入实施计划前仍需确认：

- 第一批个人研究基金池包含哪些基金代码。
- 前端第一版使用 Vue3 还是 React。

## 12. 自检结论

- 所有章节都有具体决策，未决事项集中列在实施前确认问题中。
- 产品范围限定为本地自用研究工具。
- 默认 75/15/10 配置在产品目标、流程和里程碑中保持一致。
- 基准对比已从单一基准字段调整为 experiment_group + role 模型。
- 压力区间、日度回测结果、数据质量等级和净值口径元数据已纳入设计。
- 公开产品、销售、投顾和自动交易功能已明确排除。
- 数据和计算行为已经足够支撑下一步实施计划。
